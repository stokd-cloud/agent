### Lifecycle transition oracle
The server clock and committed domain state decide transitions. A context snapshot records what the model saw, never grants authority. Every admission, side effect, approval use and finalization checks current owner/session, authority revision and the relevant coordinator or work-attempt generation; a changed remit invalidates uncommitted actions prepared against its old revision.

| Current state/event | Required transition and observable outcome |
|---|---|
| Active agent + new ordinary message | Persist ingress once; create `queued` wake in agent-wide FIFO order. A repeated commandId with identical content returns the original record; different content conflicts. |
| `queued` + eligible host, no live lease | Atomically claim next wake and generation; create a fresh attempt, OS child and DSH handle; enter `running`. Missing prerequisites leave it queued with the precise reason. |
| `running` + input/approval request | Enter `awaiting_input`; retain the same child/handle/lease only until the wake's remaining ten-minute wall-clock deadline. Ordinary messages remain separately queued. |
| Valid response before deadline | Resume the same attempt as `running`; bind response to action hash, principal, scope, authority revision and attempt. Replays/different actions cannot consume it. |
| Input deadline, denial or superseded attempt | Expire/reject the action without side effect; terminate as failed/cancelled with a typed reason. Takeover must request a new approval; no old approval survives the attempt. |
| `running` + durable executor launch receipt | Enter `completing`; atomically commit `succeeded` with outcome `work_dispatched`, dispose handle, terminate child and release/fence coordinator authority. Work remains separately submitted/running/unknown. |
| `running` + ordinary response / bounded failure | Commit journal/outcome/state proposals in `completing`, then immutable `succeeded` or `failed`. Provisional text is never a durable success acknowledgement. |
| Host loss or lease expiry before terminal commit | Fence old generation; record interrupted/reconciling attempt. Reconcile prior side-effect intent/receipt before retry; create fresh handle/context, never resume the old provider session. |
| Cancel queued/active coordinator | Queued becomes cancelled without a handle; active becomes cancelled after drain or fencing. A terminal wake returns `already_terminal`. Cancellation of an external work request is a separate acknowledged operation. |
| Worker result + active agent + continuation enabled | Persist one correlated result and at most one queued result wake. Deduplicate result ID; enqueue after already admitted messages. No eligible host means queued, not lost. |
| Worker result + archived agent, cancelled work or continuation disabled | Persist result for later inspection; create zero wake. Restore does not replay suppressed results. Explicit owner review can create one new ordinary wake. |
| Archive | Reject new ingress/dispatch immediately, cancel active coordinator, invalidate approvals; release lease only after drain/fenced expiry. Preserve independently running work/status and suppress automatic continuation. |
| Restore | Return to active with same ID/state; do not restart cancelled wakes or external work. New explicit ingress follows normal FIFO admission. |

Each successful dispatch creates a separately fenced work-attempt generation, lease and scoped broker capability. It survives terminal completion of the coordinator wake, but not work cancellation, owner/session or authority revocation, scope narrowing or its own expiry. A quarantined late receipt is audit evidence only; reconciliation may authorize verified existing output under a new generation without rerunning work. The worker never receives a reusable bearer credential or coordinator authority.

Domain work states are `requested, launching, submitted, running, awaiting_input, succeeded, failed, cancel_requested, cancelled, unknown`. Standalone launch moves requested → launching → running; the factory may remain submitted until actual executor start is observed. Backend needs-input maps to awaiting_input; backend cancel-requested maps to cancel_requested; only an observed terminal executor result maps to succeeded/failed/cancelled. Factory dev_complete/pushed/PR/landed/deployed are separately attributed delivery observations; none implies another. A launch is identified by an immutable work ID/attempt and deterministic OCI container label. A supervisor writes an intent before launch and a receipt afterward; reconciliation inspects that label before any retry. If another host cannot prove the original attempt terminal, it reports unknown/awaiting reconciliation and must not launch a replacement. A proven terminal attempt plus explicit retry can create a new attempt. Successful cancellation is claimed only after backend readback; late results remain inspectable without automatic continuation.
