### Authority and executor boundary
The coordinator has a deny-by-default tool broker allowing only domain conversation, scoped retrieval/memory proposal, questions, status and typed dispatch. DSH's final monotonic guard covers scoped registrations and reserved tools. Shell, arbitrary file writes, plugins, direct model side channels and recursive delegation are denied even if imported text requests them.

A standalone worker runs with a read-only container root and input mounts, one writable scratch/output volume, no host home/other checkout/container socket, and controlled network egress that blocks private/link-local addresses and DNS rebinding. It receives task-scoped broker capabilities for model calls, approved network retrieval, result submission and artifact upload; managed provider or owner credentials never enter the worker. The host's broker holds secrets. A missing compatible container engine is a prerequisite failure, never permission to run directly on the host.

Repository workers remain under Stokd's custody/governance/landing lifecycle. The bridge must negotiate a new `mutationScopeV1` capability before launch: the declared repo/package scope is enforced before writes, other source is read-only, scratch is separate, and supervised Git operations cannot change unrelated paths. A backend without this capability rejects the request. This is new implementation work, not a claim about the current Stokd backend; validation attempts an actual sibling-package write, not merely an out-of-scope request.

The proposed Stokd endpoint `POST /api/auth/agent-identity/attest` validates the actual user-session bearer and issues a one-use, audience-bound 60-second attestation with stable subject, source expiry and a non-secret introspection handle. The Agent service consumes it at `POST /v1/auth/stokd/exchange`. Server-to-server `POST /api/auth/agent-identity/introspect` requires a configured Agent-service identity and limits lookup to handles it issued to that service; no database access or source bearer is stored in Agent. An API key alone, client-supplied username or the legacy GitHub `me` endpoint cannot attest a user. Transport is TLS; audience/origin allowlists are operator configuration. Direct OAuth uses PKCE S256, state and exact redirect binding.
