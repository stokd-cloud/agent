# Administrator bootstrap

This is the only Agent infrastructure surface intended for a current account administrator. It initializes four empty Work 1.2 SST homes, then creates the bounded deployment role, its managed policies and boundaries, the fixed SSM command documents, and the private Agent runtime ECR repository. It does not deploy Agent data or services.

Initialization binds the existing `/sst/bootstrap` v5 record and its shared state/asset/ECR identities without creating, importing, tagging, or reconfiguring them. Under one global create-only guard, the administrator creates the six fixed stage/fallback passphrases and their encrypted empty secret objects, runs the reviewed empty SST 3.19.3 program for each app/stage, and writes immutable per-home and global receipts. Receipts retain only identity, version, tag, ciphertext, and digest metadata; they never contain decrypted passphrase values. The operator must generate and store the resume token before apply; no cloud marker is written until that token is supplied. A failed run retains its active marker and requires the same token. An existing terminal receipt is accepted only after its full binding and retained versions are reverified.

The role trusts only the existing `arn:aws:iam::167217327520:oidc-provider/token.actions.githubusercontent.com` provider with audience `sts.amazonaws.com` and subject `repo:stokd-cloud/agent:environment:agent-validation`. It has no account-root trust and creates no user or access key. Both the script and template reject every other provider ARN.

The deploy role has a permissions boundary equal to its reviewed maximum policy and exactly five attached identity policies with no inline policy. It can create or update only `stokd-agent-workload-*` roles, those roles must use the separate workload boundary, and `PassRole` is limited to EC2, ECS Tasks, and EventBridge. The routine role has explicit denies for Agent bucket/object deletion, EBS volume deletion, KMS disable/deletion, and secret deletion. Its shared SST access is limited to the exact four app/stage state namespaces, two fallback-secret identities, six read-only passphrase parameters, and retained initialization evidence. The AWS-managed SSM key is an observed external input; the role receives no direct KMS decrypt grant for it.

Review `template.yaml`, then calculate the source-and-runtime-bound acknowledgement with `node scripts/infra-bootstrap.mjs acknowledge`. Before apply, generate the recovery secret with `node scripts/infra-bootstrap.mjs resume-token`, store it securely, and export it as `AGENT_SST_INIT_RESUME_TOKEN`. Apply only by supplying the acknowledgement both as `--ack` and `AGENT_BOOTSTRAP_ACK`. The acknowledgement covers the reviewed source plus the exact SST package, launcher, native package, and executable digests; every external mutation rechecks those bytes. Routine `scripts/infra-action.mjs` commands refuse root even after this bootstrap exists.
